# The installable package: `sidewalk_panorama_tools` (store, ps_math, labels, gsv_tiles)

Loaded by Claude Code when a file matching the globs above is read. The repo-wide guidance is `CLAUDE.md` at the repo root; read it first. `docs/geometry.md` is the consumer-facing page. The geometry modules (`geometry.py`, `pose.py`, `torch_geometry.py`) and the #54 frames are `.claude/rules/tilt.md`; the store walker's history and the display-copy rules are `.claude/rules/store-repair.md`.

**What the package is for.** Consumers outside this repo (sidewalk-ai-api, sidewalk-validator-ai, RampNet, the auto-labeler scripts) pin it by tag instead of copying code. Every module here is the one definition; anything in the repo that needs the same thing imports it back, never the reverse.

- **Re-exports, never second copies.** `downloaders/common.py` re-exports `store`'s walker, sidecar predicate, `jpeg_dimensions`, `MAX_PANO_PIXELS`, `raise_decompression_bomb_ceiling` and `black_fraction`; `downloaders/gsv.py` re-exports `gsv_tiles` (`gsv.RE_EXPORTED_FROM_GSV_TILES`); `reports/scripts/pov_replay.py` re-exports all of `ps_math`. Tests assert identity (`common.X is store.X`, `pov_replay.X is ps_math.X`), so a "local fix" in the re-exporting module is a second definition and fails. `common.downscaled_sidecar_path` is the one wrapper, because the cap is a common.py decision that tests move.
- **Releases.** Bump `version` in `pyproject.toml` and `__version__` together (a test checks), record it in `docs/geometry.md` "Releases", and say what a re-pinning consumer will see change. 1.1.0 added `store`, `ps_math`, `labels` and `pillow`; 1.2.0 added `gsv_tiles`, its `[gsv]` extra and `store.black_fraction`.
- **Coverage.** Every module here is measured (`tests/test_coverage_config.py`'s exact set) and listed in `tests/test_csv_intake.py`'s `PRODUCTION_MODULES` (no pandas in production). A new module is a deliberate measure-or-omit decision.

**store.py** (#222 step 5). `read_pano` checks the header with `jpeg_dimensions` (stdlib) before Pillow is touched, reads the expected dims as `CropRunner._metadata_dims` does (`int(float(x))`), and raises `PanoDimsMismatch` only for a real mismatch; a bad argument is a plain `ValueError`. **No `warnings.catch_warnings` and no write to `Image.MAX_IMAGE_PIXELS`**: both are process-wide, and the first is not thread-safe in a server; a consumer reading 134 MP panos calls `raise_decompression_bomb_ceiling()` once. CropRunner makes the same comparison but does not call `read_pano` (one header for all of a pano's labels, lazy decode, #164).

**ps_math.py** (#222 step 6). Moved verbatim from `pov_replay.py`; `pov_from_pano_xy` is the new, unrounded inverse. `tests/test_ps_math.py` pins it against a line-by-line transcription of `UtilitiesPanomarker.js` at SidewalkWebpage v7.19.10; change the transcription only against a newer tag, and cite it. `viewport_view` stays in RampNet. CropRunner's three distance constants are still a pinned copy (`.claude/rules/cropper.md`).

**labels.py** (#222 step 4). The arithmetic, not the decision: `majority`'s `tie` and `is_validated`'s two thresholds are required keywords, so no caller inherits a policy. **The AI validator is identified by `validator_type == "AI"` and nothing else** - never a username or `user_id` in code, tests or fixtures (the fixture drops every `user_id`). An unknown `validation` or `validator_type` raises, even with AI excluded. Unsure abstains in both `majority` and `is_validated`; the threshold compares the quotient `agree / decisive`, never `fraction * decisive` (the product failed 7 of 25 at 0.28). `label_uid` refuses ids below 1 (fill values). Measured on the live API: the served `*_count` fields include AI votes, and `correct` is `majority(..., include_ai=True, tie="none")`; tests pin both on the fixture.

**gsv_tiles.py** (#222 step 2). The GSV tile fetcher, moved verbatim from `downloaders/gsv.py`: the cbk fan-out with its #162 push-back and #172 retry-budget machinery, the two-tile probe (`_probe_zoom`, public as `probe_zoom`, the same object), `frame_covers_pano`, the stitch and its black guard, `fetch_pano_image`, `choose_zoom` and `pushback_reason`. **The line it is drawn on: mechanics move, policy stays.** Ledger verdicts, run conditions, both breakers, the block latch, photometa (`ImageLevels` and the `streetlevel` request), the pace state, the display copy, the edge-band flag and the atomic save stay in `gsv.py`, which composes these functions with them; `.claude/rules/downloader.md` is the contract for both halves. Not verbatim, and only these: the three settings (`HEADERS`, `PROXIES`, `CONCURRENCY`) replace the module-level `headers_list`, `_proxies` and `thread_count` from `config.py`, which the package cannot import, so the five references to them are renamed; `configure()` is new, and `gsv.py` calls it at import with `config.py`'s values (`DEFAULT_HEADERS` is a tuple copy of `config.headers_list`, held equal by a test, because `config.py` stays the operator's file); `FrameDisagreementError`'s and `fetch_pano_image`'s docstrings describe the mechanics and name the nightly's policy as the caller's (the nightly paragraph is now a comment beside the re-export in `gsv.py`); `_BLOCK_URL_MARKERS` sits with the tile constants; and the one URL builder `tile_url` (byte for byte the three f-strings it replaced), whose base is public as `CBK_BASE_URL` (it was `_CBK_BASE_URL`; `tests/test_gsv_tiles.py` fails a second builder). **It needs the `[gsv]` extra** (`requests`, `urllib3`, `aiohttp`, `backoff`, at `requirements.txt`'s floors, a test holds them equal); the import raises an `ImportError` naming the extra, and `__init__.py` does not import it. `black_fraction` moved to `store.py`, not here, so a consumer judging a crop never needs the extra. **Two rules keep one lookup site per name.** `gsv.py`'s own code calls every moved name qualified (`gsv_tiles.PROXIES`, `gsv_tiles._request_session()`), never through a binding taken at import - `_proxies = gsv_tiles.PROXIES` would go stale on `configure()` and the photosphere and depth sessions would run without the operator's proxy; `gsv.py` keeps no `headers_list`/`proxies`/`thread_count` binding at all, so a stale patch of one raises instead of passing. And **a test patches a name on the module that looks it up**: on `gsv_tiles` for everything the package reads, and on `gsv` only for `gsv.GSV_COMPOSED_SEAMS` (`fetch_pano_image`, `frame_covers_pano`), which `download_single_pano`, `_frame_refusal` and `refetch_panos` look up on `gsv` and the package never calls. `tests/conftest.py` records every name in `gsv.RE_EXPORTED_FROM_GSV_TILES` before the first test, and `mis_targeted_patches`, run after every test's call phase, fails a test that moved the side that is not looked up (`gsv`'s binding of a package name, the package's seam), whatever the spelling - a correct patch leaves the two sides different, so the check compares each with the recorded object, never with each other; and `_no_network` refuses every non-loopback lookup and connection, so a stub that missed its seam fails instead of asking Google. `TestRequestsPerPano`'s file is unchanged; the helpers it calls were retargeted, and its counts are the proof the composition did not move.
